# 📑 Phase 3 작업 지시서: 성능 및 실시간 기능 최적화

본 지시서는 사용자 경험(UX)과 직결되는 실시간 기능의 성능을 고도화하기 위한 작업 단계를 정의합니다.

## 1. GIS(지리 정보) 조회 성능 최적화
### 1.1 쿼리 최적화 (`server/storage.ts`)
- **대상**: `getNearbyUsers`, `getExperiencesByLocation` 등.
- **작업 내용**: 
    - PostgreSQL의 `earth_distance` 또는 PostGIS 함수를 활용하여 반경 기반 조회를 최적화.
    - 대량 조회 시 커서(Cursor) 또는 페이지네이션을 적용하여 서버 메모리 과부하 방지.
- **의도 보존**: 지도 위에서 여행자를 찾거나 이벤트를 조회하는 기능의 정확도는 유지.

### 1.2 지오로케이션 보안 및 캐싱
- **작업 내용**: 
    - IP 기반 언어/위치 감지 시 동일 IP에 대해 캐싱 로직 추가 (외부 API 호출 횟수 감소).
    - `ip-api.com` 호출 시 에러 핸들링 강화.

## 2. WebSocket 연결 및 부하 관리 (`server/routes.ts`)
### 2.1 연결 상태 관리 고도화
- **작업 내용**: 
    - WebSocket 연결 시 `Heartbeat` (Ping/Pong) 주기를 30초로 설정.
    - 클라이언트 종료 시 `clients` Map에서 즉각 제거하여 고스트 세션 방지.
- **리스크**: Replit 환경의 네트워크 불안정성으로 인한 잦은 재연결 시나리오 대응 필요.

### 2.2 메시지 브로드캐스트 최적화
- **작업 내용**: 
    - 채널 메시지 브로드캐스트 시 멤버 목록 조회를 캐싱 처리하여 DB 부하 감소.
- **의도 보존**: 실시간 채팅의 전달 신뢰성 보장.

## 3. 스케줄러(Batch Job) 안정화 (`server/scheduler.ts`)
- **작업 내용**: 
    - `scheduler.ts` 내의 작업들이 서버 부하가 적은 시간에 실행되도록 `SystemConfig` 기반 스케줄 조정.
    - 작업 실행 중 에러가 발생해도 다른 배치 작업에 영향을 주지 않도록 격리 처리.
- **주의**: 배치를 종료하지 않고 부하가 집중되지 않도록 분산하는 것이 핵심.
